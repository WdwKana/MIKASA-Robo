# Research Plan — Replacing the Engineering Saliency Head with Label-Free Object-Centric Perception

Status: planning (May 2026). This document is the working context for the
next research phase. It supersedes the incremental V2/V3/V4 architecture
search (see RESEARCH_DIRECTION.md), which we now judge to have hit
diminishing returns.

---

## 1. Problem statement

The EBM-Robo pipeline works (V1 buffer dominates Remember tasks; the hybrid
adds motion-task ability), but the **single component that is not
publishable is the saliency head**:

- It is trained with per-patch BCE against the **9 hard-coded MIKASA RGB
  color codes** (`MIKASA_COLORS` in `analysis/ebm/path_a_train_head_v3.py`).
- This is privileged, task-specific supervision and pure engineering. A
  reviewer will (correctly) say the "memory" is solved by a color detector
  we hand-built.
- Everything downstream (buffer write filter, retrieval) inherits this
  weakness.

**Goal of this phase:** replace the color-BCE saliency head with a
**label-free, principled object-centric perception module** that still
"captures the task-relevant object," so the buffer stores object-grounded
tokens without privileged supervision. Object-capture precision may be
*lower* than the color head, but the mechanism must demonstrably localize
objects.

Both directions the user proposed converge on this same goal.

---

## 2. Direction 1 — VLA backbone (ReconVLA + MemVLA)

### What it is
- **ReconVLA** (arXiv 2508.10333, Aug 2025): a VLA whose diffusion
  transformer reconstructs the "gaze region" (the manipulated-object region)
  from the model's visual outputs. This *implicit grounding* objective
  forces the VLA to allocate visual attention to the target object — without
  explicit bounding-box labels. Pretrained on 100k trajectories / 2M samples.
- **MemoryVLA** (arXiv 2508.19236): perceptual+cognitive memory bank for VLA.
  We already re-implemented its memory mechanism as our `MemVLA` baseline.

### New facts (re-research, May 2026, with A100 80/90 GB available)
- **ReconVLA weights ARE released** (HF `zzyzyzy/ReconVLA`; code
  `OpenHelix-Team/ReconVLA`; trained on 8×A100-80GB). Architecture =
  reconstructive part + action part; outputs discrete action tokens +
  reconstructive tokens that drive a Flux-VAE diffusion recon of gaze regions.
- **Crucial:** ReconVLA's gaze-region targets are **generated by
  GroundingDINO / YOLO** during data prep — i.e., the grounding supervision
  is an **open-vocabulary detector**, not human boxes and not color codes.
- Related frozen-encoder VLAs: **OTTER** (frozen VL encoder, passes only
  language-aligned task-relevant features) and **ExpReS-VLA** (frozen
  SigLIP+DINOv2 features → compressed replay buffer + RAG). These confirm
  "frozen-VLA-as-feature-extractor + memory" is an active, citeable pattern.

### Compute feasibility — corrected with A100 80GB
- **Memory is no longer the wall.** A frozen 7B VLA (≈15 GB bf16) fits
  comfortably in 80 GB with room for batch-256 activations. The earlier
  "OOM on 24 GB L4" verdict only applied to L4.
- **Throughput is the remaining constraint, not a wall.** A frozen 7B forward
  at batch 256 is ~seconds/step → rollouts ~1–2 orders slower than our DINOv2
  path. Affordable for a *handful* of showcase/validation runs on A100, not
  for the full multi-task multi-seed sweep.
- **Fine-tuning the 7B online is out** (optimizer states blow past 80 GB);
  the VLA must be **frozen** and only a small head trained — same recipe as
  our frozen DINOv2.

### Verdict (revised)
VLA is **not eliminated**, but it is only sensible in two non-backbone forms:
1. **Offline teacher / label generator.** The real lever in ReconVLA is
   **GroundingDINO** producing object regions. We can run GroundingDINO (or
   frozen ReconVLA) *offline* on cached frames to produce object masks, then
   **distill** them into our lightweight saliency-sized head. This swaps the
   hand-coded color BCE for **open-vocabulary-detector supervision** — much
   less "engineering," fully citeable, and the online RL stays fast (student
   head only).
2. **Frozen feature extractor for a few A100 showcase runs.** If we want to
   claim a VLA backbone directly, run frozen ReconVLA features → buffer on
   A100 for a small set of runs, accepting the throughput cost.

This reframes Direction 1 from "VLA backbone" (infeasible) to **"open-vocab /
VLA-distilled object grounding"** (feasible). It and Direction 2 (slot
attention) are the two label-free perception candidates to test in Stage 0.

## 3. Direction 2 — Slot attention (the feasible, publishable path)

### What it is
- **DINOSAUR** (Seitzer et al., ICLR 2023, "Bridging the Gap to Real-World
  Object-Centric Learning"): frozen DINO ViT → slot attention → **reconstruct
  the DINO features from K slots**. Unsupervised object discovery on real
  images. This is *exactly* our setting — we already run a frozen DINOv2;
  we just add a slot-attention module that reconstructs its patch features.
- **SOLD** (ICML 2025): slot object-centric latent dynamics for *relational
  manipulation RL from pixels*; beats DreamerV3 and TD-MPC2. Direct precedent
  that slot-based object-centric representations help manipulation RL.

### Why it fits us
- **Reuses our frozen DINOv2** — no new backbone, no compute wall.
- Slot module is **~1–5M params, fast** → runs at batch 256 inside PPO.
- **Label-free**: trained by reconstructing DINOv2 features (DINOSAUR), no
  color codes, no privileged info.
- The K slots replace the K=8 saliency-filtered patches as buffer entries.
  The episodic K-V buffer + cross-attention reader stays unchanged.
- Reframes the whole method as **"object-centric episodic memory for
  partial-observability robot RL"** — a clean, publishable contribution that
  subsumes the engineering saliency head.

### Known risks (from the literature)
- **Clutter / foreground confusion**: strongly textured backgrounds confound
  slot binding; the robot arm and table may capture slots. Mitigations:
  Foreground-Aware Slot Attention (FASA), register slots to absorb
  background, or simply use enough slots (K ≥ #objects + arm + table).
- **Fixed slot count** and **representational fragmentation** (multiple slots
  → one object). Mitigations: slot merging, MetaSlot VQ pruning, adaptive
  slot number. For MIKASA-Robo (few objects, simple tabletop) this is
  manageable; scenes are far simpler than real-world clutter.

---

## 4. Convergent insight & proposed approach

Both directions are really asking for the same thing: **a label-free module
that grounds attention on objects.** Slot attention (DINOSAUR) achieves this
with our existing frozen DINOv2 at negligible compute; the VLA route does
not survive the compute budget.

**Primary plan: Object-Centric Episodic Memory (OCEM).**
- Perception: frozen DINOv2 → DINOSAUR-style slot attention → K object slots.
- Memory: episodic K-V buffer stores slots (not color-patches), with the same
  novelty/age priority and cross-attention reader as V1.
- (Motion ability from the V3a-LSTM hybrid carries over unchanged — it is
  orthogonal to how the buffer is *filled*.)

**Fallback signal if pure unsupervised slots don't localize the task object:**
add the ReconVLA-style reconstruction-grounding objective using a
weakly-derived target region (gripper-contact / motion), as an auxiliary loss
on the slot module — still far cheaper than a VLA backbone.

## 5. Staged experiment design

Per the user's requirement: **validate object-capture in isolation before
spending RL compute.**

### Stage 0 — perception validation (NO RL)
On cached MIKASA-Robo frames (we already have rollout dumps in
`analysis/ebm/path_a_data/`), measure whether each perception mechanism
localizes the **task-relevant object**:

| candidate | mechanism | label-free? |
|---|---|---|
| saliency head (reference) | color-BCE on DINOv2 patches | no (baseline) |
| slot attention (DINOSAUR) | reconstruct DINOv2 features from K slots | yes (unsupervised) |
| open-vocab detection | GroundingDINO text prompt → object boxes/masks | yes (no task training; pretrained) |
| VLA-distilled head (opt.) | GroundingDINO/ReconVLA masks → distill into saliency-sized head | yes (open-vocab supervision) |

**Metric:** project the ground-truth object pose (from env state —
`env.unwrapped.<obj>.pose.p`) into image space, get a target region; measure
each method's attention/slot-mask overlap:
- top-slot / top-K-patch **hit-rate** (does any slot/patch land on the
  target object?), and
- **IoU** of the best slot mask with the target region.

**Pass bar (set by the user):** the method must *demonstrate object capture*
— hit-rate clearly above chance and qualitatively landing on the object.
Precision may be below the saliency head; we are not required to beat it,
only to show the capability exists label-free.

**Compute:** trivial. Slot module trains on a few thousand cached frames in
minutes on one GPU; evaluation is a forward pass. No cluster jobs needed.

### Stage 1 — RL integration (gated on Stage 0 passing)
- Swap the buffer's write source from saliency-top-K to slot tokens.
- Run RememberColor5 / RememberShape5 / RememberColor9 (the tasks where the
  buffer is load-bearing), 3 seeds each, same PPO config.
- Compare to the saliency-head EBM (V1) and to the no-saliency A3 baseline.
- Success: OCEM should match or approach saliency-EBM on Remember tasks
  **without using color labels**. Matching A3-level (no-saliency) would be a
  failure; matching V1-level would be the win.

Only after Stage 1 shows parity do we expand to the full task suite and the
motion-task hybrid.

---

## 6. Success criteria (explicit)

- **Stage 0:** slot attention achieves object hit-rate ≳ 60% on the
  task-relevant object across Remember tasks (vs the saliency head as the
  upper reference), with qualitative overlays showing slots on objects.
- **Stage 1:** OCEM (slot-buffer) reaches ≥ 80% of the saliency-EBM (V1)
  SR_once on RememberColor5 / Shape5, with zero privileged color supervision.
- If both pass: the paper's perception story changes from "we hand-built a
  color detector" to "unsupervised object-centric slots drive episodic
  memory," which is publishable.

---

## 7. Compute budget

- Stage 0: single-GPU, hours total (slot training + eval). No SLURM array.
- Stage 1: same cost as existing EBM runs (slot module adds ~1–5M params and
  one extra forward; negligible vs frozen DINOv2). 3 tasks × 3 seeds ≈ 9
  runs, same ~5–6 h/run as current pipeline.
- VLA backbone: explicitly excluded (infeasible, §2).

---

## 8. Risks & mitigations

| risk | mitigation |
|---|---|
| Slots bind to robot arm / table, not the task object | foreground-aware slot attention; more slots; register slots; or weak motion/contact prior |
| Slot attention unstable on some tasks | use DINOSAUR feature-reconstruction (most stable variant); fix slot count per task family |
| Unsupervised slots don't isolate the *task-relevant* object (e.g., which of 3 cubes) | this is expected — the buffer + reader learn relevance downstream; Stage 0 only requires capturing objects, not picking the right one |
| Stage 0 fails entirely | fall back to ReconVLA-style recon-grounding with a weak target prior, still no color labels |

## 8b. Stage-0 result — slot attention (RememberColor9, May 2026)

DINOSAUR slots (frozen DINOv2 → slot attention → feature reconstruction)
trained unsupervised on cached RC9 frames, evaluated vs color-derived GT:

| input | grid | slots | mean best-IoU | recall=1 hit | verdict |
|---|---|---|---|---|---|
| 126 | 9×9 | 6 | 0.023 | 1.00 | coarse |
| 224 | 16×16 | 8 | 0.014 | 0.99 | fragments |

Interpretation (overlays in `analysis/slot/stage0_vis/`):
- A slot **always contains** the target cube (recall ≈ 1.0), so "capture
  exists" in the weak sense, **but no slot isolates it** (best IoU ≈ 0.02).
- At 9×9 the best slot is a coarse "cubes+table" blob; at 16×16 it
  **fragments** into scattered table-texture patches. Higher resolution
  makes it worse, not better.
- Root cause: RememberColor cubes are 1–2 patches; slot attention binds to
  dominant scene structure (table texture, arm), and is **color-agnostic**,
  so it never separates the task-relevant colored cube — which is exactly
  what the task needs.

**Verdict: pure unsupervised slot attention is NOT a drop-in replacement for
the color saliency head on the RememberColor/Shape family.** It fails the
"isolate the target object" bar (precision far below saliency; capture only
in the trivial recall sense).

**Pivot:** the more promising label-free path for these *small* objects is
**open-vocabulary detection (GroundingDINO)** — precise boxes/masks for small
objects, text-promptable ("cube"/"colored block"), pretrained (no task
training), and it is exactly the mechanism ReconVLA uses to generate its
grounding targets. Next Stage-0 test: GroundingDINO hit-rate/IoU on the same
frames, then distill into a saliency-sized head if it localizes well.

## 8c. Pivot — replace saliency with a memory-intrinsic mechanism

After the Stage-0 slot result, the strongest direction is to **abandon any
external pre-attention module (saliency, slot, GroundingDINO) entirely and
let the memory mechanism itself decide what to write.** This is a cleaner
mechanism-level story than "we found a better object detector."

### Proposed mechanism — Predictive Episodic Memory (PEM)

> Episodic memory is the systematic representation of surprise. We replace
> the engineering saliency head with a **self-predictive** buffer: the
> memory maintains an implicit forward model of the world, and the write
> filter is exactly the model's prediction error.

Concrete pipeline (drop-in replacement for the saliency head):
1. Frozen DINOv2 → patch features `p_t` at time `t` (unchanged).
2. **Small predictor** `f_θ`: given recent buffer summary + `p_{t-1}`,
   predicts the next-step patch features `p̂_t`.
3. **Per-patch surprise** `s_t[n] = ‖p_t[n] − p̂_t[n]‖²`.
4. **Write gate**: top-K patches by `s_t` are pushed to the K-V buffer
   (no color labels, no GroundingDINO, no slots).
5. Buffer eviction, cross-attention reader, fuse — all unchanged from V1.
6. Predictor trained online via an MSE auxiliary loss on rollout data;
   no extra supervision.

### Why this works as a mechanism story
- **Saliency emerges from temporal dynamics, not from labels.** The
  predictor learns "what the world usually does"; novelty against that
  prior is automatically the colored cue, the moving ball, the gripped
  object — exactly the things a saliency head is supposed to find.
- **One principle covers both task families:**
  - *Remember*: the cube being revealed at t≈0 is a one-shot surprise
    (predictor never saw it before in this episode) → written. Later
    steps without the cube are predictable → not written. The cue stays
    in the buffer.
  - *Motion*: the ball's trajectory residual (after the predictor's
    coarse extrapolation) is surprise → ball patches are continually
    written → trajectory accumulates in the buffer.
- **Removes the publishability liability** (no MIKASA color codes).
- **Composes orthogonally with the V3a-LSTM hybrid** (action-coherence
  branch is independent of how the buffer is filled).

### Lineage / precedents the story rests on
- **Predictive coding** — Rao & Ballard (1999); the long-standing
  neuroscience framing that the brain encodes prediction residuals.
- **Curiosity-driven exploration (ICM)** — Pathak et al. 2017; uses
  prediction error as intrinsic reward for *exploration*.
- **Surprise Memory (Le et al., arXiv 2308.04836)** — uses an autoencoder
  + attention episodic memory that *stores and reconstructs surprises*
  for novelty-as-intrinsic-reward. Same building block, different
  niche (exploration, not partial-observability robot memory).
- **Hippocampal-surprise literature** (Nature/eLife 2023 papers in the
  refs) — prediction error gates episodic encoding in biological memory.
- **MemoryVLA / Chameleon (2025)** — recent VLA memory modules; neither
  uses a prediction-error write gate. *White space.*

### Falsifiable predictions vs. the saliency head
1. PEM should match V1 (saliency-EBM) on RememberColor5 / Shape5
   (Stage 1 target ≥ 80% of V1).
2. PEM should *exceed* V1 on tasks where color labels were a poor proxy
   for relevance (Intercept family, possibly).
3. The predictor's prediction-error map should qualitatively land on the
   colored cube in early-episode frames (Stage 0 sanity).

### Stage 0' — sanity-check PEM offline
Before any RL run:
- Train the predictor on cached rollout features (`path_a_data/`).
- Visualize per-patch prediction-error overlays on the same RC9 frames we
  used for slot Stage 0. Pass bar: error reliably lights up on the
  colored cube when it is shown.
- Compare error-top-K patches against the saliency-top-K patches as a
  reference — they should overlap on the cue frames.

### Stage 1' — RL integration (only if Stage 0' passes)
- Swap V1's saliency-top-K write for PEM's surprise-top-K write.
- Run RC5 / Shape5 / RC9 / IGrabMed × 3 seeds, same PPO config.
- Compare to V1 (with color saliency) and to A3 (no saliency / random K).
- Success = match V1 within ~20% on Remember tasks AND match V3a on
  IGrabMed — claiming the entire pipeline with zero color supervision.

### Risks & mitigations
- **Cold-start**: predictor untrained early in PPO → everything looks
  surprising → buffer is noise. Mitigations: pretrain the predictor on
  cached random-policy rollouts before RL; or use an EMA-of-features
  predictor as warm start.
- **Action-driven surprise contaminates writes**: the gripper itself
  moves → its patches always have residual error. Mitigations: condition
  the predictor on `action_{t-1}` so self-motion is predictable, and only
  reward-irrelevant motion remains as "surprise."
- **Reward-coupled drift**: as the policy improves, surprise distribution
  shifts. Mitigations: continual predictor training; periodic reset.

## 9. Immediate next actions (revised, post-pivot)

1. Implement the **predictor** module: small MLP/transformer that, given the
   last few patch feature maps (and optionally `action_{t-1}`), predicts the
   next patch feature map. Output a per-patch L2 surprise score.
2. **Stage 0'** — offline sanity: train the predictor on cached rollout
   features (`path_a_data/`), plot surprise overlays on RC9 frames, compare
   to the color saliency head and to the previous slot-attention overlays.
   Pass if surprise reliably highlights the cube.
3. **Stage 1'** — only after Stage 0' passes: a single PEM module that
   drops into the existing V1 EBM pipeline (top-K-by-surprise replaces
   top-K-by-saliency); 3 seeds on RC5 / Shape5 / RC9 / IGrabMed.
4. Compare to V1 (with the color head) and to A3 (no head, random K).

Slot attention is paused — confirmed too coarse on this benchmark (§8b).
Open-vocab detection (GroundingDINO) is held in reserve as a fallback if
PEM also fails on small static cues.
